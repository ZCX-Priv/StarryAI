# 完善错误处理计划

## Summary
将现有的流式响应错误从"普通 Markdown 文本渲染"改为"结构化错误消息卡片"：带圆圈的叉图标 + 固定提示文案，下方提供"重新生成"和"错误信息"按钮；点击"错误信息"弹出模态框展示完整原始错误内容。同时向后兼容已有错误消息数据。

## Current State Analysis
- `Message.status` 已支持 `'error'`，但错误时把 `⚠ ${error.message}` 直接写入 `message.content`，导致错误文本被当作 Markdown 正常渲染。
- `MessageBubble.tsx` 对 `status === 'error'` 没有特殊处理，错误消息和普通 AI 回复视觉一致。
- `MessageActions.tsx` 固定在消息列表末尾提供"重新生成/复制"，与错误消息分离，用户体验不佳。
- 项目已有自定义 Modal 体系（`modal-overlay` + `modal` CSS），不需要引入新依赖。

## Proposed Changes

### 1. 扩展消息类型
**文件：** `src/types/index.ts`
- 在 `Message` 接口增加可选字段 `errorInfo?: string`，用于保存原始错误文本，与展示文案分离。

### 2. 封装错误设置逻辑
**文件：** `src/hooks/useChats.ts`
- 新增 `setMessageError(chatId, messageId, errorInfo)`：一次性把对应消息更新为 `content: ''`、`errorInfo`、`status: 'error'`。

### 3. 新建错误详情弹窗
**文件：** `src/components/modals/ErrorDetailDialog.tsx`
- 复用现有 Modal 结构（`modal-overlay`、`modal`、`modal-hd`、`modal-body`、`modal-footer`）。
- Props：`visible`、`onClose`、`errorInfo`。
- 标题：错误信息。
- Body 内用 `<pre>` 展示完整 `errorInfo`，支持换行和滚动。
- Footer：仅一个"关闭"按钮。

### 4. 消息气泡支持错误状态渲染
**文件：** `src/components/chat/MessageBubble.tsx`
- Props 新增 `onRegenerate?: () => void` 和 `errorInfo?: string`。
- 当 `status === 'error'` 时，不再渲染 `MarkdownRenderer`，而是渲染错误卡片：
  - 顶部：lucide-react `XCircle` 图标 + "AI模型响应错误，请稍后重试"。
  - 底部按钮行（复用/仿照 `msg-action-btn` 样式）：
    - "重新生成"：调用 `onRegenerate`。
    - "错误信息"：打开本地状态弹窗，把 `errorInfo` 传给 `ErrorDetailDialog`。
- **兼容性：** 若旧数据没有 `errorInfo`，回退使用 `content`（去掉已有的 `⚠ ` 前缀）。

### 5. 消息列表调整
**文件：** `src/components/chat/MessageList.tsx`
- 向 `MessageBubble` 传递 `msg.errorInfo` 和 `onRegenerate`。
- 调整 `MessageActions` 的显示条件：仅当最后一条 AI 消息**不是** `'error'` 状态时才显示，避免错误消息下方出现重复的"重新生成/复制"。

### 6. 更新流式请求错误处理（发送消息）
**文件：** `src/components/chat/InputArea.tsx`
- 在 `handleSend` 的 `catch` 块中，将原来的：
  ```tsx
  updateMessageContent(chatId, assistantMsgId, `⚠ ${e instanceof Error ? e.message : 'Error'}`);
  await setMessageStatus(chatId, assistantMsgId, 'error');
  ```
  替换为一次 `setMessageError(chatId, assistantMsgId, e instanceof Error ? e.message : 'Error')` 调用。

### 7. 更新流式请求错误处理（重新生成）
**文件：** `src/components/chat/ChatArea.tsx`
- 在 `handleRegenerate` 的 `catch` 块中，做与 InputArea 相同的替换。

### 8. 样式补充
**文件：** `src/index.css`
- 在 `/* Messages */` 区块补充 `.msg-error-content`、`.msg-error-icon`、`.msg-error-text` 等样式，保持与现有消息风格一致（圆角、字号、颜色使用语义变量）。

## Assumptions & Decisions
1. **内容分离：** 错误展示文案固定为"AI模型响应错误，请稍后重试"，原始错误存入 `errorInfo`，不污染 `content`。
2. **弹窗复用：** 使用项目已有的 `.modal-overlay` 体系，不引入 shadcn Dialog，保持风格统一。
3. **向后兼容：** 旧错误消息没有 `errorInfo` 字段，渲染时若 `errorInfo` 缺失则回退读取 `content`。
4. **按钮去重：** 错误消息自带"重新生成"，因此 `MessageActions` 在错误状态下隐藏，避免同一界面出现两个"重新生成"。
5. **不改动 Toast：** 现有的 `showToast('请求失败...', 'error')` 保留，作为额外弱提示。

## Verification Steps
1. 在 `InputArea.tsx` 中临时把请求 URL 改错，发送消息，观察消息列表是否出现：圆圈叉 + "AI模型响应错误，请稍后重试" + 两个按钮。
2. 点击"重新生成"，确认能够重新触发流式请求。
3. 点击"错误信息"，确认弹出模态框并显示完整错误文本。
4. 确认错误消息下方**没有**额外出现 `MessageActions` 的"复制"按钮。
5. 运行 `npm run lint` 和 `npx tsc --noEmit` 确保无类型和语法错误。
